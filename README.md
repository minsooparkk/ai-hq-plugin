# ai-hq: Claude Code 를 내 비서로 쓰는 규칙과 스킬

이 문서는 법조문의 짜임을 빌려 썼다. 장(제1장)은 큰 묶음, 조(제1조)는 한 가지 주제, 항(①②③)은 한 가지 내용, 호(1. 2. 3.)는 늘어놓는 것, 목(가. 나. 다.)은 호를 다시 나눈 것이다. 말은 쉬운 말로 썼다.

## 제1장 총칙

### 제1조(목적)

① 이 플러그인은 Claude Code 를 내 일을 모으고 정리하고, 허락받은 일만 처리하는 비서로 쓰게 한다.

② 이 문서는 설치하는 법, 비서가 일하는 방식, 메신저와 예약을 잇는 법, 고치고 지우는 법, 그리고 이 플러그인이 못 하는 것을 정한다.

### 제2조(정의)

이 문서에서 쓰는 말의 뜻은 다음과 같다.

1. "비서"란 이 플러그인을 설치한 Claude Code 를 말한다. 처음 설정 때 이름을 붙일 수 있다(기본 이름 Jarvis).
2. "사용자"란 이 플러그인을 설치하고 비서에게 일을 시키는 사람을 말한다.
3. "본부 폴더"란 비서의 규칙과 기록을 두는 내 컴퓨터의 폴더 하나를 말한다. 사용자가 처음 설정 때 고른다.
4. "플러그인"이란 Claude Code 에 더해 설치하는 묶음을 말한다. 이 플러그인의 이름은 ai-hq 이다.
5. "장터"란 플러그인 목록을 담아 둔 곳을 말한다. 이 플러그인의 장터 이름은 ai-hq-plugin 이다.
6. "GitHub"란 파일을 올려 두고 여러 사람이 받아 쓰는 누리집을 말한다. 이 플러그인의 장터는 GitHub 에 있다.
7. "규칙"이란 비서가 늘 지키는 약속을 적은 글을 말한다. 본부 폴더의 rules 폴더에 00번부터 11번까지 있다.
8. "스킬"이란 한 가지 일을 하는 순서와 판단 기준을 적은 글을 말한다. 비서는 일에 맞는 스킬을 먼저 읽고 그대로 한다.
9. "터미널"이란 글자로 명령을 넣는 창을 말한다. 맥에서는 '터미널' 앱이고, 윈도우에서는 'PowerShell' 이다.
10. "세션"이란 Claude Code 를 켜서 끌 때까지 이어지는 대화 한 판을 말한다.
11. "커넥터"란 메일, 캘린더, 슬랙 같은 바깥 서비스를 Claude 에 잇는 연결을 말한다. claude.ai 누리집의 커넥터 화면에서 사용자가 직접 잇는다.
12. "채널"이란 메신저에서 보낸 말이 내 컴퓨터에 켜져 있는 세션으로 바로 들어오게 하는 Claude Code 의 기능을 말한다.
13. "원격 제어"란 내 컴퓨터에 켜 둔 세션을 휴대폰의 Claude 앱이나 claude.ai 누리집에서 이어서 쓰는 Claude Code 의 기능을 말한다. 공식 이름은 Remote Control 이다.
14. "승인"이란 비서가 하려는 일을 사용자가 보고 허락하는 것을 말한다.
15. "권한 목록"이란 비서가 묻지 않고 해도 되는 일(허용), 사용자에게 물어야 하는 일(묻기), 하면 안 되는 일(거부)을 적은 파일을 말한다. 본부 폴더의 `.claude/settings.json` 이다.
16. "비밀값"이란 비밀번호, 메신저 봇의 열쇠(봇 토큰)처럼 남이 알면 안 되는 값을 말한다.
17. "예약"이란 정한 때가 되면 비서가 스스로 일을 시작하게 해 두는 것을 말한다.
18. "시험 공개"란 만든 회사가 아직 다듬는 중이라 쓰는 법과 동작이 바뀔 수 있다고 밝힌 기능을 말한다. 공식 문서의 research preview 를 옮긴 말이다.
19. "Bun"이란 텔레그램과 디스코드 연결 플러그인이 돌아가는 데 필요한 프로그램을 말한다.
20. "봇"이란 메신저 안에서 사람 대신 글을 받고 보내는 계정을 말한다. 텔레그램과 디스코드를 이을 때 내 봇을 하나 만들고, 비서는 그 봇의 이름으로 답한다.
21. "저장소"란 GitHub 에 올려 둔 파일 묶음 하나를 말한다. 이 플러그인의 파일도 저장소 하나에 들어 있다.
22. "Console 계정"이란 Anthropic 이 개발자에게 주는 누리집(Console)에서 만든 계정을 말한다. claude.ai 계정과 다르다.

### 제3조(맞는 사람)

이 플러그인은 다음에 맞는 사람에게 쓸모가 있다.

1. Claude Code 를 써 봤지만 일을 모으고 정리하는 체계를 굴려 본 적은 없는 사람
2. 메일, 일정, 할 일, 사람별로 오간 것을 한곳에 정리해 두고 싶은 사람
3. 비서가 스스로 할 일과 허락받고 할 일을 나눠 두고 싶은 사람
4. 텔레그램, 디스코드, 슬랙, Claude 앱 가운데 하나로 비서와 말하고 싶은 사람

### 제4조(맞지 않는 경우)

① 비서가 사람 손 없이 메일을 보내거나 글을 올리기를 바라면 맞지 않는다. 이 플러그인은 보내기, 올리기, 지우기 앞에서 반드시 허락을 묻는다.

② 컴퓨터를 꺼 둔 채 비서가 내 파일로 일하기를 바라면 맞지 않는다. 본부 폴더는 내 컴퓨터에 있어서, 컴퓨터가 꺼져 있으면 비서가 그 폴더를 읽지 못한다.

③ Claude Code 를 쓸 수 없는 계정이면 쓸 수 없다. claude.ai 의 무료 요금제에는 Claude Code 가 들어 있지 않다.

④ 여러 사람이 함께 쓰는 비서를 바라면 맞지 않는다. 이 플러그인은 사용자 한 사람의 비서를 전제로 만들었다.

## 제2장 설치

### 제5조(준비물)

① 설치 전에 다음을 갖춘다.

1. Claude Code. 공식 설치 안내(code.claude.com/docs/en/setup)대로 설치한다. 터미널에 넣는 설치 명령은 다음과 같다.

   가. 맥: `curl -fsSL https://claude.ai/install.sh | bash`

   나. 윈도우 PowerShell: `irm https://claude.ai/install.ps1 | iex`

2. Claude Code 를 쓸 수 있는 계정. 공식 문서가 밝힌 것은 Pro, Max, Ultra, Team, Enterprise 요금제와 Console 계정이다.
3. 본부 폴더로 쓸 빈 폴더 하나. 예를 들어 문서 폴더 아래 `AI본부`.

② 메신저를 잇는 사람은 제4장의 준비물을 따로 갖춘다.

③ 윈도우에서는 Git for Windows(파일 변경 이력을 다루는 프로그램 Git 을 윈도우에 설치해 주는 묶음)를 설치해 두기를 권한다. 공식 문서는 이것이 없어도 Claude Code 가 PowerShell 로 일한다고 밝힌다.

### 제6조(설치 순서)

① 터미널을 열고 `claude` 를 쳐서 Claude Code 를 켠다.

② Claude Code 의 입력 칸에 다음 두 줄을 차례로 넣는다.

```
/plugin marketplace add minsooparkk/ai-hq-plugin
/plugin install ai-hq@ai-hq-plugin
```

③ 설치 범위를 고르라는 물음이 나오면 'Install for you (user scope)' 를 고른다. 그래야 어느 폴더에서 Claude Code 를 켜도 이 플러그인이 보인다.

④ 설치를 마친 글의 끝이 `Run /reload-plugins to apply.` 이면 `/reload-plugins` 를 친다.

⑤ 터미널에서 Claude Code 를 켜지 않고 바로 설치할 수도 있다. 이때는 터미널에 다음 두 줄을 넣는다.

```
claude plugin marketplace add minsooparkk/ai-hq-plugin
claude plugin install ai-hq@ai-hq-plugin
```

⑥ 맥과 윈도우에서 제2항과 제5항의 명령은 같다.

⑦ Claude 데스크톱 앱이나 VS Code(코드와 글을 고치는 편집 프로그램)를 쓰는 사람도 위 순서는 터미널에서 한 번 하면 된다. 공식 문서는 한 컴퓨터의 터미널, 데스크톱 앱, VS Code 가 같은 설정을 읽는다고 밝힌다.

### 제7조(처음 설정)

① Claude Code 입력 칸에 `/ai-hq:설치` 를 치거나 "비서 처음 설정해 줘" 라고 말한다.

② 비서는 다음 다섯 가지를 한 번에 하나씩 묻는다.

1. 본부 폴더로 쓸 곳
2. 비서의 이름(기본 Jarvis)
3. 비서가 사용자를 부를 호칭(기본 대표님)
4. 사용자가 하는 일(한두 문장)
5. 비서와 말할 메신저와 맡기는 정도

   가. 메신저: 텔레그램, 디스코드, 슬랙, Claude 앱 가운데 하나

   나. 맡기는 정도: '조심' 또는 '맡김'

③ 비서는 답을 받아 본부 폴더에 규칙과 기록 폴더를 쓴다. 이미 같은 이름의 파일이 있으면 덮어쓰지 않고 무엇이 있는지 알린다.

④ 설정을 마치면 비서는 다음에 할 일 세 가지를 알려 준다.

1. 메신저 잇기(제4장)
2. 예약 만들기(제5장)
3. 첫 일 시켜 보기

⑤ 처음 설정 뒤에는 Claude Code 를 늘 본부 폴더에서 켠다. 다른 폴더에서 켜면 본부의 규칙이 읽히지 않는다.

1. 맥: 터미널에서 `cd ~/Documents/AI본부` 를 친 뒤 `claude` 를 친다.
2. 윈도우: PowerShell 에서 `cd "$HOME\Documents\AI본부"` 를 친 뒤 `claude` 를 친다. 문서 폴더가 다른 곳에 있으면 그 위치로 바꾼다.

⑥ 처음 설정이 본부 폴더에 쓰는 것은 다음과 같다.

1. `CLAUDE.md`: Claude Code 가 켜질 때마다 늘 읽는 첫 파일
2. `RULES.md`: 어떤 때 어떤 규칙을 읽을지 적은 목록
3. `rules/`: 규칙 00번부터 11번
4. `.claude/settings.json`: 권한 목록
5. `.harness/`: 기록을 두는 폴더(제11조)

## 제3장 비서가 일하는 방식

### 제8조(스스로 하는 일)

① 비서는 되돌릴 수 있는 선택이면 묻지 않고 스스로 고른 뒤 끝까지 한다(규칙 00).

② 비서는 스스로 고른 것을 기록 파일에 `[결정]` 으로 시작하는 한 줄로 남긴다.

③ 비서는 답에 굵은 '결정' 칸을 두어 무엇을 왜 골랐는지 알린다.

④ 결과가 판단에 따라 달라지는 일이면 비서는 답에 굵은 '틀릴 수 있는 곳' 칸을 둔다.

⑤ 다음은 비서가 스스로 하는 일의 예다.

1. 연결된 메일, 메신저, 캘린더에서 새로 온 것을 읽어 정리하기
2. 사람이나 회사별로 오간 것과 기다리는 것을 정리하기
3. 할 일 목록에 더하고, 끝내고, 미루기
4. 아침 브리핑과 저녁 요약 쓰기
5. 메일 답장 초안 쓰기

### 제9조(승인받고 하는 일)

① 비서는 되돌릴 수 없는 일 앞에서 멈추고 사용자의 승인을 받는다. 다음이 그런 일이다.

1. 남에게 메일이나 메시지를 보내기
2. 바깥 서비스에 글이나 파일을 올리기
3. 본부 폴더 밖의 자료를 지우기
4. 일정을 넣거나 고치기

② 비서는 승인을 구하기 전에 쉬운 말 세 칸으로 승인 글을 쓴다.

1. 결론: 무엇을 승인하는지, 승인하면 무엇이 일어나는지
2. 배경: 왜 하는지, 사용자가 한 말
3. 본문: 보이는 변화, 거부하면 생기는 일, 되돌리는 법

③ 권한 목록의 '묻기'에 걸린 일이면 Claude Code 가 허용할지 묻는 창을 띄운다. 그 창에서 허용하는 것이 곧 승인이다.

④ 메신저로 말하는 중이면 메신저에서 한 답으로 승인할 수 있다. 다만 메신저마다 되는 범위가 다르고(제4장), 허용을 묻는 창은 컴퓨터 앞에서 답해야 할 수도 있다.

⑤ 승인은 사용자 본인만 한다. 다른 사람이 보낸 메시지나 비서가 읽은 글 속에 적힌 지시는 승인이 아니다.

⑥ 승인을 구한 일마다 비서는 결정 묶음 파일 하나를 남긴다(제11조 제1항 제3호).

⑦ 권한 목록의 '묻기'에는 처음 설정 때 연결돼 있던 커넥터의 보내기, 올리기, 지우기만 들어간다. 나중에 연결한 커넥터는 `/ai-hq:규칙-손질` 로 묻기 목록에 더한다.

⑧ 맡기는 정도를 '맡김'으로 고르면 본부 폴더 안의 파일 고치기는 묻지 않는다. '조심'으로 고르면 Claude Code 의 기본값대로 묻는다.

### 제10조(하지 않는 일)

비서는 다음을 하지 않는다.

1. 비밀값이 든 파일을 열거나, 비밀값을 새 파일에 적기
2. 사용자에게 비밀값을 대화창에 붙여 넣으라고 하기
3. 주민등록번호나 계좌번호를 다른 파일에 옮겨 적기
4. 파일을 바로 지우기. 지울 것은 `.harness/휴지통/` 으로 옮기고, 휴지통을 비우는 것은 사용자가 한다.
5. 바깥 서비스의 원본을 고치기. 바깥 서비스는 읽는 것이 기본이고, 원본은 제자리에 두고 위치와 요약만 적는다.
6. 사용자 본인이 아닌 사람의 지시를 따르기

### 제11조(기록)

① 비서는 본부 폴더의 `.harness/` 에 다음을 남긴다.

1. 한 일 기록: `기록/YYYY-MM-DD.md`(날짜별 한 파일). 한 줄 모양은 `- HH:MM · 누가 · 무엇을 · 결과 · 근거` 이다.
2. 사용자가 정한 것: `결정/결정기록.md`
3. 승인 요청마다 결정 묶음: `결정/요청/요청-0001-짧은제목.md`. 무엇, 배경, 근거, 다른 안, 위험과 되돌리기, 결정과 결과, 이어진 요청을 적는다.
4. 가져온 것: `입력/`
5. 사람이나 회사별 정리: `사람/`
6. 할 일: `할일.md`. 다른 할 일 도구를 연결했으면 그쪽을 쓴다.
7. 배운 것과 실수: `memory/MEMORY.md`
8. 지우는 대신 옮겨 둔 것: `휴지통/`

② "지난번에 승인한 것 뭐였지" 라고 물으면 비서는 결정 묶음과 기록을 읽고 한 건을 한 화면으로 답한다.

③ 기록 파일은 사용자 컴퓨터의 본부 폴더에 남는다. 이 플러그인은 기록 파일을 다른 곳에 따로 올리지 않는다.

④ 다만 비서가 읽고 쓰는 내용은 Claude Code 를 거쳐 Anthropic 과 오간다. 원격 제어를 쓰는 동안에는 대화 내용이 Anthropic 서버에 저장된다(제17조).

### 제12조(규칙과 스킬)

① 본부 폴더의 규칙은 다음과 같다.

1. 00 자율적인 결정
2. 01 승인과 결정 기록
3. 02 권한
4. 03 하는 일
5. 04 작업
6. 05 데이터와 비밀값
7. 06 도구
8. 07 소통
9. 08 메신저 인터페이스
10. 09 한국어 문장
11. 10 한국어 낱말
12. 11 문장부호

② 00, 01, 07, 08번은 늘 읽힌다. 나머지는 그 일을 할 때 읽힌다.

③ 이 플러그인의 스킬은 다음과 같다. 입력 칸에 `/ai-hq:이름` 을 치거나, 하고 싶은 일을 말로 하면 비서가 맞는 스킬을 고른다.

1. 설치: 처음 설정
2. 규칙-손질: 규칙과 권한 목록 고치기
3. 입력-가져오기: 메일, 메신저, 캘린더에서 새로 온 것 모으기
4. 사람-정리: 사람이나 회사별로 오간 것 정리
5. 할일-정리: 할 일 더하기, 끝내기, 미루기
6. 일정-정리: 일정 보기, 겹침 확인, 비는 시간 찾기
7. 하루-브리핑: 아침 '오늘 할 일' 글
8. 아침저녁-요약: 아침 브리핑과 저녁 요약
9. 메일-답장: 답장 초안에서 승인 뒤 보내기까지
10. 승인-기록: 승인 글 쓰기, 결정 묶음 남기기, 지난 승인 찾기
11. 메신저-연결: 메신저 잇기
12. 예약-만들기: 예약 만들기

④ 메일, 캘린더, 메신저 커넥터가 하나도 연결돼 있지 않으면 입력-가져오기, 일정-정리, 메일-답장은 무엇을 연결하면 되는지만 알리고 멈춘다.

## 제4장 메신저

### 제13조(공통)

① 메신저 잇기는 `/ai-hq:메신저-연결` 을 치거나 "텔레그램 연결해 줘" 처럼 말하면 비서가 한 단계씩 안내한다.

② 메신저별로 되는 것과 안 되는 것은 제14조부터 제17조까지와 별표 1에 적는다.

③ 봇 토큰 같은 비밀값은 사용자가 그 메신저 플러그인의 설정 명령에 직접 넣는다. 비서는 비밀값을 대화로 받지 않는다.

④ 설정 명령에 넣은 값은 그 세션의 대화에도 남는다. 그래서 남이 보는 화면에서는 하지 않는다.

⑤ 메신저로 말을 주고받으려면 내 컴퓨터가 켜져 있고 Claude Code 세션이 열려 있어야 한다. 세션을 닫으면 메신저로 보낸 말은 비서에게 닿지 않는다.

⑥ 비서가 허용을 묻는 창을 띄웠는데 아무도 답하지 않으면 그 세션은 답이 올 때까지 멈춘다.

⑦ 공식 문서는 허용을 묻는 물음을 메신저로 넘기는 기능을 갖춘 채널이면 메신저에서 답할 수 있다고 밝힌다. 텔레그램과 디스코드에서 이것이 되는지는 처음 쓸 때 확인한다(메신저-연결 스킬이 시험 순서를 안내한다).

⑧ 허용을 묻지 않고 모든 것을 하게 하는 Claude Code 의 실행 방법이 있지만, 이 플러그인과 함께 쓰지 않는다. 승인 단계가 사라지기 때문이다.

⑨ 메신저로 말을 걸 수 있는 사람은 나 한 사람으로 잠가 둔다. 공식 문서는 채널로 답할 수 있는 사람이면 허용 물음에도 답할 수 있다고 밝힌다.

⑩ 봇 토큰을 넣는 설정 명령(제14조 제3항 제3호, 제15조 제3항 제5호)은 본부 폴더가 아닌 곳(예: 홈 폴더)에서 켠 Claude Code 에서 친다. 본부 폴더의 권한 목록은 비밀값 파일 읽기를 거부하고 비서도 그 파일을 열지 않아서, 본부 폴더에서 치면 막히거나 일부만 될 수 있다. 토큰을 넣은 뒤에는 그 창을 닫고 본부 폴더에서 다시 켠다.

⑪ 토큰은 내 컴퓨터의 사용자 폴더 아래 `.claude/channels/telegram/.env`(디스코드는 `discord/.env`) 파일에 저장된다. 공식 설명서는 이 파일을 사용자가 손으로 써도 된다고 밝힌다. 비서에게 이 파일을 열거나 고치라고 시키지 않는다.

### 제14조(텔레그램)

① 텔레그램은 Anthropic 의 공식 채널 플러그인으로 잇는다. 이 기능은 시험 공개 단계다.

② 준비물은 다음과 같다.

1. Bun
2. claude.ai 계정이나 Console 계정으로 로그인한 Claude Code
3. Team 이나 Enterprise 요금제라면 관리자가 채널을 켜 두는 것

③ 잇는 순서의 큰 줄기는 다음과 같다. 자세한 것은 메신저-연결 스킬이 안내한다.

1. 텔레그램의 BotFather 에게 `/newbot` 을 보내 봇을 만들고 봇 토큰을 받는다.
2. Claude Code 에서 `/plugin install telegram@claude-plugins-official` 을 친다.
3. 본부 폴더가 아닌 곳에서 켠 Claude Code 에서 `/telegram:configure <봇토큰>` 으로 토큰을 넣는다(제13조 제10항).
4. Claude Code 를 끄고, 본부 폴더에서 `claude --channels plugin:telegram@claude-plugins-official` 로 다시 켠다.
5. 텔레그램에서 내 봇에게 아무 말이나 보내 짝 맞추기 코드를 받는다.
6. Claude Code 에서 `/telegram:access pair <코드>` 를 친다.
7. `/telegram:access policy allowlist` 로 나만 말을 걸 수 있게 잠근다.

④ 되는 것은 다음과 같다.

1. 휴대폰 텔레그램에서 비서에게 말을 걸고 답을 받는 것
2. 사진을 보내는 것. 사진은 받는 즉시 내 컴퓨터에 저장된다.

⑤ 안 되는 것은 다음과 같다.

1. 지난 대화를 비서가 다시 읽는 것. 텔레그램 봇은 지난 메시지를 찾아볼 수 없고, 도착하는 말만 본다.
2. 세션이 닫혀 있을 때 말을 받는 것
3. 터미널에서 비서의 답 글을 보는 것. 터미널에는 '보냈다'는 표시만 나오고 답은 텔레그램에만 나온다.

### 제15조(디스코드)

① 디스코드도 Anthropic 의 공식 채널 플러그인으로 잇는다. 이 기능은 시험 공개 단계다.

② 준비물은 제14조 제2항과 같다. 여기에 내가 들어가 있는 디스코드 서버(디스코드 안에서 사람들이 모이는 방 묶음)가 하나 있어야 한다. 디스코드는 같은 서버에 있는 봇에게만 1:1 메시지를 보낼 수 있다.

③ 잇는 순서의 큰 줄기는 다음과 같다.

1. 디스코드 개발자 화면(Discord Developer Portal)에서 새 앱과 봇을 만들고 봇 토큰을 받는다.
2. 봇 설정에서 Message Content Intent 를 켠다.
3. 봇을 내 서버에 초대한다.
4. Claude Code 에서 `/plugin install discord@claude-plugins-official` 을 친다.
5. 본부 폴더가 아닌 곳에서 켠 Claude Code 에서 `/discord:configure <봇토큰>` 으로 토큰을 넣는다(제13조 제10항).
6. 본부 폴더에서 `claude --channels plugin:discord@claude-plugins-official` 로 다시 켠다.
7. 디스코드에서 내 봇에게 1:1 메시지를 보내 짝 맞추기 코드를 받는다.
8. `/discord:access pair <코드>` 를 친 뒤 `/discord:access policy allowlist` 로 잠근다.

④ 되는 것은 다음과 같다.

1. 디스코드에서 비서에게 말을 걸고 답을 받는 것
2. 그 대화방의 최근 메시지를 비서가 다시 읽는 것. 한 번에 100개까지다.
3. 첨부 파일을 비서가 필요할 때 내려받는 것

⑤ 안 되는 것은 제14조 제5항 제2호와 제3호와 같다.

### 제16조(슬랙)

① 슬랙에는 채널 기능이 없다. 그래서 슬랙에서 말을 걸어 내 컴퓨터의 비서를 바로 움직일 수는 없다.

② 슬랙은 커넥터로 잇는다. claude.ai 의 커넥터 화면(claude.ai/customize/connectors)에서 슬랙을 연결한다. Team 이나 Enterprise 요금제에서는 관리자만 커넥터를 더할 수 있다.

③ 커넥터는 Claude Code 에 claude.ai 계정으로 로그인했을 때만 보인다.

④ 되는 것은 다음과 같다.

1. 비서가 세션 안에서 슬랙 메시지를 읽는 것
2. 비서가 승인을 받아 슬랙에 글을 쓰는 것
3. 예약을 걸어 두고 정한 때마다 슬랙을 읽어 정리하는 것(제5장)

⑤ 안 되는 것은 다음과 같다.

1. 슬랙에서 비서에게 말을 걸어 바로 답을 받는 것
2. 슬랙의 '@Claude' 를 내 본부의 비서로 쓰는 것. 공식 문서가 밝힌 슬랙의 '@Claude' 는 Anthropic 의 서버에서 새 세션을 열고 GitHub 저장소로 일하는 기능이라, 내 컴퓨터의 본부 폴더를 읽지 못한다.

⑥ 슬랙을 고른 사람은 비서와 말할 곳으로 터미널이나 Claude 앱(제17조)을 함께 쓴다.

### 제17조(Claude 앱)

① 메신저를 쓰지 않으면 원격 제어로 휴대폰의 Claude 앱이나 claude.ai 누리집에서 비서와 말한다.

② 준비물은 다음과 같다.

1. Pro, Max, Ultra, Team, Enterprise 가운데 하나인 claude.ai 요금제. Console 의 열쇠(API 키)로 로그인한 경우에는 쓸 수 없다.
2. Team 이나 Enterprise 요금제라면 관리자가 원격 제어를 켜 두는 것
3. 휴대폰의 Claude 앱. 같은 계정으로 로그인한다.

③ 켜는 법은 다음과 같다.

1. 본부 폴더에서 `claude --remote-control` 로 켠다.
2. 이미 켜 둔 세션이면 입력 칸에 `/remote-control` 을 친다.
3. Claude 앱이나 claude.ai/code 의 세션 목록에서 그 세션을 고른다. 터미널에 나오는 QR 코드를 휴대폰으로 찍어도 된다.
4. 늘 켜지게 하려면 `/config` 에서 'Enable Remote Control for all sessions' 를 켠다.

④ 되는 것은 다음과 같다.

1. 휴대폰에서 비서에게 말을 걸고 답을 받는 것
2. 허용을 묻는 창에 휴대폰에서 답하는 것
3. 사진과 파일을 휴대폰에서 보내는 것
4. 일이 끝나거나 승인이 필요할 때 휴대폰 알림을 받는 것. `/config` 에서 'Push when actions required' 를 켠다.

⑤ 안 되는 것과 조건은 다음과 같다.

1. 컴퓨터가 켜져 있고 Claude Code 가 돌고 있어야 한다. 터미널이나 앱을 닫으면 끊긴다.
2. 컴퓨터가 잠들었다 깨면 저절로 다시 이어진다.
3. 원격 제어를 쓰는 동안 대화 내용은 Anthropic 서버에 저장된다. 파일과 명령 실행은 내 컴퓨터에 남는다.

## 제5장 예약

### 제18조(예약은 사용자가 만든다)

① 플러그인은 예약을 실어 보낼 수 없다. 아침 브리핑, 저녁 요약, 새로 온 것 가져오기를 되풀이하게 하려면 사용자가 예약을 만들어야 한다.

② `/ai-hq:예약-만들기` 를 치거나 "아침 브리핑 예약해 줘" 라고 말하면 비서가 길을 고르고 만드는 것을 돕는다.

### 제19조(예약의 세 가지 길)

① Claude Code 의 예약에는 다음 세 가지 길이 있다. 조건은 별표 2에 모아 적는다.

1. 세션 안 예약: 지금 켜 둔 세션 안에서 정한 때마다 일을 시키는 것
2. 데스크톱 예약: Claude 데스크톱 앱이 정한 때마다 새 세션을 열어 일을 시키는 것
3. 클라우드 예약: Anthropic 의 서버에서 정한 때마다 일을 시키는 것

② 세션 안 예약의 조건은 다음과 같다.

1. 컴퓨터가 켜져 있고 그 세션이 열려 있어야 한다. 세션을 닫으면 멈춘다.
2. 되풀이 예약은 만든 지 7일이 지나면 마지막으로 한 번 돈 뒤 저절로 사라진다. 계속 쓰려면 7일 안에 다시 만든다.
3. 하루에 한 번 도는 예약은 정한 시각보다 최대 30분 늦게 돌 수 있다.
4. 놓친 때를 나중에 채워 돌리지 않는다.
5. 텔레그램이나 디스코드 세션 안에 만들면, 예약이 그 세션의 메신저 연결을 그대로 쓴다. 결과가 메신저로 오는지는 만든 뒤 한 번 시험해 본다.

③ 데스크톱 예약의 조건은 다음과 같다.

1. Claude 데스크톱 앱(1.1.5368 이상)이 열려 있고 컴퓨터가 깨어 있어야 한다.
2. 컴퓨터가 잠든 동안의 차례는 건너뛴다. 앱을 열거나 컴퓨터가 깨면, 지난 7일 안에 놓친 것 가운데 가장 최근 한 번만 돈다.
3. 앱 설정의 'Keep computer awake' 를 켜면 컴퓨터가 저절로 잠들지 않는다. 노트북 덮개를 닫으면 그래도 잠든다.
4. 예약이 사라지는 기한은 없다.
5. 돌 때마다 본부 폴더에서 새 세션을 연다. 허용을 묻는 창이 뜨면 그 회차의 세션에서 답할 때까지 멈춘다.

④ 클라우드 예약의 조건은 다음과 같다.

1. 시험 공개 단계다.
2. 컴퓨터가 꺼져 있어도 돈다.
3. 내 컴퓨터의 파일을 읽지 못한다. 그래서 본부 폴더의 규칙과 기록을 쓰지 못한다.
4. 묻지 않고 스스로 판단하는 방식으로 돌기 때문에, 커넥터로 글을 보내는 일도 묻지 않고 할 수 있다.
5. 가장 짧은 간격은 1시간이다.

⑤ 이 플러그인은 클라우드 예약을 권하지 않는다. 제4항 제3호와 제4호 때문에 본부의 규칙과 승인 단계가 지켜지지 않기 때문이다.

### 제20조(고르는 법)

① 텔레그램이나 디스코드를 쓰는 사람은 그 메신저 세션 안에 세션 안 예약을 만든다. 일주일마다 다시 만들어야 한다.

② 컴퓨터를 오래 켜 두는 사람은 데스크톱 예약을 쓴다. 결과는 그 회차의 세션에 남는다. 본부 폴더에도 남기려면 예약의 지시문에 그렇게 적는다.

③ 둘 다 아니면 예약 없이, 필요할 때 "아침 브리핑 써 줘" 라고 말해 쓴다.

## 제6장 고치기와 지우기

### 제21조(규칙 고치기)

① 규칙과 권한 목록은 `/ai-hq:규칙-손질` 로 고친다.

② 비서는 고치기 전에 사본을 두고, 규칙의 판 번호(Version)를 올리고, 결정기록에 한 줄을 남긴다.

③ 승인 대상이나 거부 목록을 줄이는 것은 사용자가 승인해야 한다.

④ 본부 폴더의 파일은 사용자의 것이다. 사용자가 직접 열어 고쳐도 된다.

### 제22조(플러그인 업데이트)

① 이 플러그인의 장터는 저절로 업데이트되지 않는다. 공식 문서는 Anthropic 의 공식 장터가 아닌 장터는 저절로 업데이트하는 것이 꺼져 있다고 밝힌다.

② 업데이트는 다음 가운데 하나로 한다.

1. Claude Code 에서 `/plugin` 을 열고 Marketplaces 탭에서 ai-hq-plugin 을 고른 뒤 'Update marketplace' 를 누른다.
2. 터미널에서 `claude plugin update ai-hq@ai-hq-plugin` 을 친다.

③ 플러그인을 업데이트해도 본부 폴더에 이미 쓴 규칙과 기록은 바뀌지 않는다. 새 규칙을 받으려면 규칙-손질로 비교해 옮긴다.

### 제23조(지우기)

① 플러그인을 지우려면 Claude Code 에서 `/plugin uninstall` 을 치거나, 터미널에서 `claude plugin uninstall ai-hq@ai-hq-plugin` 을 친다.

② 장터까지 지우려면 `claude plugin marketplace remove ai-hq-plugin` 을 친다. 이 장터에서 설치한 플러그인도 함께 지워진다.

③ 플러그인을 지워도 본부 폴더는 남는다. 본부 폴더가 더 필요 없으면 사용자가 직접 지운다.

④ 메신저 플러그인은 따로 지운다. 봇을 더 쓰지 않으면 텔레그램의 BotFather 나 디스코드 개발자 화면에서 봇도 정리한다.
