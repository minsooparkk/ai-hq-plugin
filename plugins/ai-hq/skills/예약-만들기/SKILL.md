# 예약-만들기

플러그인은 예약을 실어 보낼 수 없다. 그래서 사용자와 함께 Claude Code 의 예약 기능으로 만든다. 아래 사실은 공식 문서(code.claude.com/docs/en/scheduled-tasks, desktop-scheduled-tasks, routines)에서 확인한 것만 적었다. 여기에 없는 것은 "공식 문서에 적혀 있지 않다"고 말한다.

## 무엇을 예약하나

| 일 | 기본 때 | 예약에 넣을 지시문 |
|---|---|---|
| 아침 브리핑 | 매일 09:00 | 스킬 아침저녁-요약으로 아침 브리핑을 쓴다 |
| 저녁 요약 | 매일 18:00 | 스킬 아침저녁-요약으로 저녁 요약을 쓴다 |
| 새로 온 것 가져오기 | 한 시간마다 | 스킬 입력-가져오기로 새로 온 것을 가져온다 |

1. 때는 사용자에게 한 번 묻고, 답이 없으면 기본 때로 한다. 평일만 원하면 평일로 한다.
2. 지시문에는 늘 "본부 폴더의 규칙을 지킨다. 보내기, 올리기, 지우기는 하지 않고 승인 글만 남긴다" 를 붙인다.
3. 메신저 세션(아래 1길)이면 지시문 끝에 "결과를 메신저로 보낸다" 를 붙인다.

## 길 고르기

사용자에게 두 가지만 묻는다.

1. 비서와 말하는 곳: 본부 폴더의 `CLAUDE.md` 에 적힌 메신저를 먼저 본다.
2. 컴퓨터를 켜 두는 편인지, Claude 데스크톱 앱을 쓰는지

| 사용자 | 권하는 길 |
|---|---|
| 텔레그램이나 디스코드 세션을 늘 켜 둔다 | 1길 세션 안 예약 |
| 데스크톱 앱을 쓰고 컴퓨터를 켜 둔다 | 2길 데스크톱 예약 |
| 둘 다 아니다 | 예약 없이 필요할 때 "아침 브리핑 써 줘" |

3길 클라우드 예약은 권하지 않는다(아래 3길의 까닭).

## 1길. 세션 안 예약

지금 켜 둔 세션 안에서 정한 때마다 지시문을 돌린다.

조건을 먼저 알린다.
- 컴퓨터가 켜져 있고 이 세션이 열려 있어야 한다. 세션을 닫으면 멈춘다.
- 되풀이 예약은 만든 지 7일이 지나면 마지막으로 한 번 돈 뒤 사라진다.
- 하루 한 번이나 한 시간마다 도는 예약은 정한 때보다 최대 30분 늦게 돌 수 있다. 같은 예약은 늘 같은 만큼 늦는다.
- 비서가 다른 일을 하는 중이면 그 일이 끝난 뒤에 돈다. 놓친 차례를 나중에 여러 번 채워 돌리지 않는다.
- 시각은 이 컴퓨터의 시간대로 본다. 한 세션에 50개까지 둘 수 있다.

만드는 순서.
1. 비서가 자기 예약 도구(CronCreate)로 만든다. 다섯 칸 시각 표현을 쓴다: 아침 `0 9 * * *`, 저녁 `0 18 * * *`, 한 시간마다 `7 * * * *`, 평일 아침 `0 9 * * 1-5`.
2. 만들고 나면 다음 차례 시각을 사용자에게 알린다.
3. 사용자가 직접 만들고 싶어 하면 이렇게 친다: `/loop 1h 스킬 입력-가져오기로 새로 온 것을 가져온다`. `/loop` 는 간격(1h 같은)만 받으므로, 매일 몇 시처럼 시각을 정하려면 비서에게 말로 시킨다.
4. 메신저 세션이면 예약이 그 세션의 메신저 연결을 그대로 쓴다. 결과가 메신저로 오는지 처음 한 번은 "지금 한 번 돌려 봐" 로 시험한다.
5. 7일 기한 때문에 `.harness/할일.md` 에 "예약 다시 만들기" 를 만든 날에서 6일 뒤 날짜로 한 줄 넣는다. 그날 이 스킬로 다시 만든다.

알아 둘 것.
- 세션을 껐다 켤 때 `claude --continue` 로 이어서 켜면 기한이 안 지난 예약이 돌아온다. 닫혀 있던 동안 놓친 차례는 돌지 않는다.
- 메신저 연결 명령(`claude --channels ...`)과 `--continue` 를 함께 쓸 수 있는지는 공식 문서에 적혀 있지 않다. 안 되면 다시 켠 뒤 예약을 다시 만든다.
- 목록은 "예약 뭐 있어?", 취소는 "아침 브리핑 예약 취소해 줘" 로 한다(CronList, CronDelete).

## 2길. 데스크톱 예약

Claude 데스크톱 앱이 정한 때마다 본부 폴더에서 새 세션을 열어 지시문을 돌린다. 데스크톱 앱은 맥용과 윈도우용이 있다. 이 플러그인은 윈도우에서 예약을 시험해 본 적이 없다.

조건을 먼저 알린다.
- 데스크톱 앱(1.1.5368 이상)이 열려 있고 컴퓨터가 깨어 있어야 한다.
- 컴퓨터가 잠든 동안의 차례는 건너뛴다. 앱을 열거나 컴퓨터가 깨면, 지난 7일 안에 놓친 것 가운데 가장 최근 한 번만 돈다. 아침 9시 예약이 밤 11시에 돌 수도 있다.
- 사라지는 기한은 없다.
- 정한 때보다 몇 분 늦게 돈다(예약마다 늘 같은 만큼).
- 허용 물음이 뜨면 그 회차는 답할 때까지 멈춘다.

만드는 순서. 이 스킬을 데스크톱 앱 세션에서 쓰고 있으면 먼저 비서가 말로 바로 만들 수 있는지 본다(공식 문서: 데스크톱 세션에서 "매일 아침 9시에 ~" 라고 하면 예약이 생긴다). 안 되면 사용자에게 화면 순서를 한 단계씩 안내한다.
1. Code 탭의 옆줄(사이드바)에서 Scheduled 를 누른다(안 보이면 옆줄의 More 메뉴 안, 옛 화면이면 Routines).
2. New task 를 누른다. 'Create with Claude' 와 'Set up manually' 가 나오면 Set up manually 를 고른다.
3. Name 에 이름(예: 아침-브리핑), 아래 칸에 위 표의 지시문을 넣는다.
4. Advanced settings 의 General 에서 'Only on this computer' 를 켠다.
5. Local folder 에 본부 폴더를 고른다.
6. Trigger 에서 Daily, Weekdays, Hourly 가운데 하나와 시각을 고른다.
7. 권한 방식은 본부의 맡기는 정도에 맞춘다. '맡김'이면 Accept edits, '조심'이면 바꾸지 않는다. 모든 허용을 건너뛰는 방식은 고르지 않는다.
8. Create 를 누른다. 폴더를 믿겠느냐고 물으면 허용한다.
9. 상세 화면에서 Run now 를 눌러 한 번 돌리고, 뜨는 허용 물음을 확인한다. 보내기, 지우기처럼 묻기 목록에 있는 것은 '늘 허용'하지 않는다.

알아 둘 것.
- 앱 설정(Settings 의 Desktop app, 또는 This computer 의 System)에서 'Keep computer awake' 를 켜면 컴퓨터가 저절로 잠들지 않는다. 노트북 덮개를 닫으면 그래도 잠든다.
- 늦게 도는 경우를 대비해 지시문에 "정한 시각보다 3시간 넘게 늦었으면 글 맨 앞에 늦은 회차라고 적는다" 를 붙인다.
- 결과 글은 그 회차의 세션에 남는다(상세 화면의 History). 데스크톱 예약의 결과가 텔레그램이나 디스코드로 가는지는 공식 문서에 적혀 있지 않다. 메신저로 받고 싶으면 1길을 쓴다.
- 멈추기는 상세 화면의 Status 를 Paused 로, 지우기는 Delete 로 한다. 지워도 지시문 파일 폴더(사용자 폴더의 `.claude/scheduled-tasks/이름/`)는 남는다.

## 3길. 클라우드 예약(권하지 않음)

Anthropic 서버에서 돈다. 시험 공개 단계다. 컴퓨터가 꺼져 있어도 돌지만 다음 까닭으로 이 플러그인과 맞지 않는다.
- 내 컴퓨터의 파일을 읽지 못한다. 본부 폴더의 규칙, 기록, 할 일을 쓰지 못한다.
- 묻지 않고 스스로 판단하는 방식으로 돈다. 넣어 둔 커넥터로 보내기와 쓰기도 할 수 있다.
- 가장 짧은 간격은 1시간이다. claude.ai/code/routines 나 `/schedule` 로 만든다.

사용자가 그래도 원하면 위 세 가지를 알리고, 꼭 필요한 커넥터만 남기게 하고, 만드는 것은 사용자가 직접 하게 한다.

## 안 돌았다고 할 때

1. 1길: 그 세션이 열려 있었는지, 7일이 지났는지 본다. "예약 뭐 있어?" 로 남아 있는지 본다.
2. 2길: 상세 화면의 History 에서 건너뛴 차례에 마우스를 올려 까닭(잠듦, 앞 회차가 아직 돎, 다른 예약이 돌던 중)을 본다. 허용 물음에서 멈춘 회차가 있는지 본다.
3. 까닭과 고친 것을 `.harness/memory/MEMORY.md` 에 한 줄 남긴다.

## 끝내기

1. 기록 한 줄: `- HH:MM · 비서 이름 · 예약 만들기(무엇을, 언제, 어느 길) · 됨 또는 막힘 · 스킬 예약-만들기`
2. 답은 결과부터: 만든 예약 목록(일, 때, 길), 다음 차례 시각, 사용자가 할 일(예: 7일 뒤 다시 만들기, 앱 열어 두기).
3. 굵은 '틀릴 수 있는 곳' 칸에 이번 길의 약한 곳을 한 줄 적는다(예: 세션을 닫으면 멈춤, 잠든 동안 건너뜀).
