# 규칙 손질

본부 폴더의 규칙(CLAUDE.md, RULES.md, rules/)과 권한(`.claude/settings.json`)을 고치는 순서다. 플러그인의 스킬 문서는 고치지 않는다. 새 판이 나오면 덮이기 때문이다(rules/06-도구.md 4번).

## 언제 쓰나

- 사용자가 규칙이나 권한을 바꾸라고 할 때.
- 같은 실수가 두 번 나서 규칙에 반영할 때(rules/00-자율적인-결정.md 5번).
- 커넥터를 새로 연결해서 그 보내기 도구를 묻기 목록에 넣을 때.

## 1. 무엇을 고칠지 정한다

| 바꾸려는 것 | 고칠 파일 |
|---|---|
| 일하는 방식, 말투, 글쓰기 | `rules/NN-이름.md` 가운데 맞는 파일 |
| 어떤 상황에 어떤 규칙을 읽나 | `RULES.md` |
| 매번 읽히는 규칙 목록 | `CLAUDE.md` 맨 위의 `@` 줄 |
| 묻지 않고 할 것, 물어볼 것, 못 하게 할 것 | `.claude/settings.json` |

새 규칙이 기존 규칙과 겹치면 새 절을 만들지 않고 기존 절을 고친다. 한 규칙은 한 곳에만 둔다.

## 2. 사용자 승인이 필요한지 본다

| 고치는 것 | 누가 정하나 |
|---|---|
| 묻기(ask)나 거부(deny) 목록에서 빼기, 줄이기 | 사용자 승인 |
| 승인 단계의 일(rules/02-권한.md 1번)을 허용(allow) 목록에 넣기 | 사용자 승인 |
| rules/02-권한.md 1번의 승인 단계, 금지 단계에서 항목 빼기 | 사용자 승인 |
| 묻기, 거부 목록에 더하기 | 비서가 하고 알린다 |
| 되돌릴 수 있는 일을 허용 목록에 더하기 | 비서가 하고 알린다 |
| 규칙 글 다듬기, 규칙 더하기, 색인 고치기 | 비서가 하고 알린다 |

사용자 승인이 필요하면 rules/01-승인과-결정-기록.md 대로 승인 글 세 칸을 쓰고 결정 묶음을 남긴다(스킬 승인-기록). 사용자가 대화에서 "앞으로는 묻지 말고 해" 라고 직접 말했어도, 무엇이 묻지 않게 되는지 승인 글로 한 번 보여 주고 답을 받는다.

## 3. 고치기 전에 사본을 둔다

고칠 파일을 `.harness/휴지통/YYYY-MM-DD/` 에 같은 이름으로 복사해 둔다. 같은 날 두 번째 사본이면 이름 끝에 `-2` 를 붙인다.

## 4. 규칙 파일을 고친다

- 틀을 지킨다: 제목, `> **Version**: x.y.z`, 적용 범위 한 문단, `## Core Rules`, `### N. 주제 - 판정`, 본문. 예와 예외는 **Correct**, **Incorrect**, **Exceptions** 줄로 적는다.
- Version을 올린다. 글만 다듬으면 끝자리(1.0.0에서 1.0.1), 규칙을 더하거나 빼거나 바꾸면 가운데 자리(1.0.0에서 1.1.0), 틀을 다시 짜면 첫 자리(1.0.0에서 2.0.0).
- 번호를 바꿨으면 그 번호를 가리키는 다른 규칙과 RULES.md를 같이 고친다. 본부 폴더 안에서 `rules/NN-이름.md N번` 꼴을 찾아본다.
- 한 파일은 1만 자 안쪽으로 둔다. 매번 읽히는 파일(CLAUDE.md가 부르는 것)은 짧게 둔다.
- 글은 rules/09-한국어-문장.md, rules/10-한국어-낱말.md, rules/11-문장부호.md를 따른다.

## 5. 권한 목록을 고친다

`.claude/settings.json` 의 `permissions` 아래 `allow`, `ask`, `deny` 목록에 규칙을 한 줄씩 넣는다. 한 일이 여러 목록에 걸리면 거부, 묻기, 허용 순서로 먼저 걸린 것이 정한다.

| 막거나 열 것 | 규칙의 꼴 | 예 |
|---|---|---|
| 터미널 명령(맥, 윈도우의 Git Bash) | `Bash(명령 *)` | `Bash(git push *)` |
| 윈도우 PowerShell 명령 | `PowerShell(명령 *)` | `PowerShell(Remove-Item *)` |
| 파일 읽기 | `Read(위치)` | `Read(//**/.env)` |
| 파일 고치기와 새로 쓰기 | `Edit(위치)` | `Edit(/rules/**)` |
| 커넥터 도구 하나 | `mcp__서버__도구` | `mcp__claude_ai_Gmail__send_message` |
| 커넥터 하나의 모든 도구 | `mcp__서버__*` | `mcp__claude_ai_Gmail__*` |

- 위치의 꼴: `/` 로 시작하면 본부 폴더 기준, `~/` 는 사용자 홈 폴더 기준, `//` 는 컴퓨터 맨 위 기준이다. `**` 는 그 아래 모든 폴더다.
- 새로 쓰기만 막는 `Write(위치)` 규칙은 듣지 않는다. `Edit(위치)` 로 쓴다.
- `mcp__` 규칙에는 괄호를 붙이지 않는다. 괄호가 붙으면 Claude Code가 그 규칙을 건너뛴다.
- 지우는 명령을 막을 때는 맥과 윈도우 둘 다 넣는다. `Bash(rm *)` 와 `PowerShell(Remove-Item *)` 처럼.
- 명령 규칙은 글자를 보고 가린다. 같은 일을 다른 꼴로 쓰면 걸리지 않을 수 있다. 그래서 묻기 목록은 마지막 울타리가 아니다. 승인 단계의 일은 목록과 상관없이 승인받는다.
- 이 파일은 엄격한 JSON이다. 주석과 마지막 쉼표를 넣지 않는다. 고친 뒤 다시 읽어 괄호와 쉼표를 확인한다.
- 이 파일을 고칠 때 Claude Code가 허락을 물을 수 있다. 사용자에게 허용을 눌러 달라고 한다.
- 저장하면 Claude Code가 바뀐 설정을 다시 읽는다. 다음 도구 사용부터 적용되는지 `/permissions` 로 볼 수 있다고 알린다.

## 6. 남긴다

- `.harness/결정/결정기록.md` 맨 아래에 한 줄: `- YYYY-MM-DD 무엇을 바꿨나. 사용자가 한 말: "원문". 걸리는 곳: 파일 이름과 절 번호.` 사용자가 시키지 않고 비서가 고친 것이면 사용자가 한 말 칸에 까닭을 쓴다.
- `.harness/기록/YYYY-MM-DD.md` 에 한 줄: `- HH:MM · 비서 이름 · 규칙 손질 · 무엇을 바꿨나, 새 Version · 사본 위치`

## 7. 알린다

결과부터 쓴다. 무엇이 바뀌었는지, 언제부터인지, 되돌리려면 무엇을 하면 되는지(사본 위치는 작업용 칸에). 사용자 승인이 필요했던 것이면 결정 묶음 번호를 `요청 0001` 처럼 함께 쓴다.

## 멈출 때

- 2절에서 사용자 승인이 필요한 것인데 답이 없으면 고치지 않는다. 기다리는 동안 다른 일은 계속한다.
- 고친 권한 파일을 다시 읽었을 때 JSON이 깨졌으면 사본으로 바로 되돌리고 알린다.
- 비밀값(토큰, 비밀번호)을 규칙이나 권한 파일에 적으라는 요청은 하지 않는다(rules/05-데이터와-비밀값.md 4번).
