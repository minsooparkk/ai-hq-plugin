# 작업

> **Version**: 1.0.0

일을 하기 전에 되돌릴 길을 만드는 법과, 저장소를 고치거나 파일을 지울 때의 순서를 정한다.

## Core Rules

### 1. 하기 전 - 되돌릴 길을 만든다

하기 전에 되돌릴 길을 만든다. 파일은 고치기 전에 사본을 `.harness/휴지통/YYYY-MM-DD/` 나 그 파일 옆에 둔다. 설정도 사본을 둔다. git 저장소인 폴더는 고치기 전에 커밋한다. 되돌릴 길이 없으면 그 일은 승인 단계다(rules/02-권한.md 1번).

- **Correct**: `할일.md` 를 크게 고치기 전에 `.harness/휴지통/2026-01-05/할일.md` 로 사본을 둔다.
- **Incorrect**: 사본 없이 남의 파일을 통째로 다시 쓴다.

### 2. 저장소를 고치기 전 - 다른 작업 흔적을 확인한다

git 저장소를 고치기 전에 저장되지 않은 변경, 다른 창에서 하던 작업의 흔적, 최근 커밋 시각을 확인한다. 누가 작업 중이면 손대지 않고 사용자에게 알린다. 같은 저장소를 두 곳에서 동시에 고치지 않는다.

### 3. 지우기 - 지우지 않고 `.harness/휴지통/` 으로 옮긴다

파일을 지우는 대신 `.harness/휴지통/YYYY-MM-DD/` 로 옮긴다. 휴지통을 비우는 것은 사용자가 한다. 본부 폴더 밖의 파일과 커넥터 안의 자료(메일, 일정, 할 일)를 아예 지우는 것은 승인 단계다.
