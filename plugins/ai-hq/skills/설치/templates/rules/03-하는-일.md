# 하는 일

> **Version**: 1.0.0

사용자 요청을 받아 어떻게 할지, 새 일을 어떤 모양으로 만들지, 기록 폴더 어디에 무엇을 쓰고 어디는 읽기만 하는지 정한다.

## Core Rules

### 1. 사용자의 요청 - 직접 처리한다

사용자의 요청은 직접 처리한다. 찾기, 사람과 회사의 지난 일, 할 일, 일정, 초안 쓰기 모두 네 일이다. 방법은 스킬을 따른다(rules/06-도구.md).

### 2. 하위 작업에 맡길 때 - 사용자 설명을 빠짐없이 옮기고 결과를 검토한다

Claude Code의 하위 작업(Agent 도구)에 맡길 때는 사용자가 한 설명(왜, 어떤 말투로, 전에 한 말, 하지 말라고 한 것)을 맡기는 글에 빠짐없이 옮긴다. 맡은 쪽은 그 글만 보고 일한다. 결과는 직접 검토해 받아들이거나 다시 맡긴다. 가능하면 쓴 쪽과 검토하는 쪽을 다른 모델로 둔다.

### 3. 새 일 - 순서가 정해진 일은 스킬 문서와 예약으로

같은 순서로 되풀이하는 일은 그때그때 새로 궁리하지 않고 정해 둔다.

1. 들어오는 길과 나가는 길은 연결된 커넥터가 먼저다. 커넥터가 없을 때만 브라우저를 쓴다.
2. 서로 기다릴 필요 없는 재료는 동시에 모은다.
3. 판단하는 단계의 순서와 기준은 스킬 문서에 적는다.
4. 언제 돌지는 예약으로 정한다(스킬 예약-만들기).
5. 반드시 지켜야 하는 것은 글로 부탁하지 말고 권한 목록(묻기, 거부)으로 막는다(rules/02-권한.md 2번).

### 4. 비서를 더 둘 때 - 새 상대, 새 권한 경계, 오래 도는 일일 때만

다른 비서 폴더를 따로 만드는 것은 세 경우뿐이다. 새 상대(사람)가 있을 때, 다른 권한(새 비밀값이나 고칠 수 있는 곳)이 필요할 때, 대화하는 동안에도 뒤에서 30분 넘게 도는 일이 있을 때. 그 밖은 스킬과 예약으로 둔다.

### 5. 기록 폴더 - 쓰는 곳과 읽기만 하는 곳

쓰는 곳은 본부 폴더의 `.harness/` 이다.

| 위치 | 적는 것 |
|---|---|
| `기록/YYYY-MM-DD.md` | 한 일. 한 건에 한 줄 |
| `결정/결정기록.md` | 사용자가 정한 것. 새 결정은 맨 아래 |
| `결정/요청/요청-0001-짧은제목.md` | 승인 요청마다 결정 묶음 한 파일(rules/01-승인과-결정-기록.md 5번) |
| `입력/YYYY-MM-DD.md` | 가져온 것. 마지막으로 가져온 때는 `입력/가져온-때.md`(스킬 입력-가져오기) |
| `사람/이름.md` | 사람이나 회사별 정리(스킬 사람-정리) |
| `할일.md` | 할 일. 할 일 커넥터를 연결하지 않았을 때 쓴다. 비서가 이어서 할 일은 제목 앞에 `[비서]`(스킬 할일-정리) |
| `memory/MEMORY.md` | 배운 것과 실수 |
| `휴지통/` | 지우는 대신 옮겨 두는 곳(rules/04-작업.md 3번) |

한 일 기록 한 줄의 모양은 `- HH:MM · 누가 · 무엇을 · 결과 · 근거` 이다. 스스로 고른 결정은 무엇을 칸을 `[결정] 물음` 으로 시작한다(rules/00-자율적인-결정.md 1번). 줄은 파일 맨 아래에 덧붙이고, 이미 있는 줄은 고치지 않는다.

읽기만 하는 곳은 연결된 메일, 캘린더, 메신저와 본부 폴더 밖 사용자의 파일이다. 사용자가 시키지 않으면 고치지 않는다.
